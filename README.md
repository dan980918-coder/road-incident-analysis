# 도로 돌발상황 분석

ITS 국가교통정보센터의 도로 돌발상황 데이터(약 62.3만 건, 2024-11 ~ 2025-10)로 돌발
유형·시간대·계절·도로 특성별 발생 패턴을 분석하고, 각 돌발 레코드에 위험도 점수를 매겨
어떤 유형·도로·시간대에 대응 자원을 우선 배치해야 하는지 근거를 찾는 프로젝트입니다.

## 프로젝트 개요

2015년 약 2,099만 대였던 국내 자동차 등록 대수는 2024년 약 2,630만 대까지 매년 꾸준히
늘었다(국토교통부 시도별 자료 기준). 도로 위 교통량이 늘어난다는 것은 교통사고·공사·
차량고장 등 돌발상황이 발생할 여지도 함께 늘어난다는 뜻이고, 이는 곧 혼잡·지체·안전사고
위험 증가로 이어져 도로를 이용하는 사람들의 일상에 영향을 준다.

이 프로젝트는 그 돌발상황 자체를 데이터로 뜯어봐서

1. 어떤 유형의 돌발이, 언제(시간대·요일·계절), 어떤 도로에서 많이 발생하는지 패턴을 찾고
2. 그 패턴을 근거로 어떤 상황이 실제로 "더 위험한지" 정량적으로 줄을 세워보고
3. 그 결과를 바탕으로 순찰·공사 일정·사고 대응 인력 배치 같은 교통운영에 참고할 만한
   시사점을 도출하는 것을 목표로 한다.

## 데이터

- 출처: [ITS 국가교통정보센터](https://www.its.go.kr) 오픈데이터 API (돌발정보)
- 기간: 2024-11-06 ~ 2025-10-31 (1년)
- 규모: 약 62.3만 행, 15개 컬럼(돌발일시, 도로타입, 도로명, 돌발구분, 돌발상세구분,
  돌발내용, 위경도, 돌발종료일시 등)
- 컬럼별 상세 스키마와 저장소 포함 방식(gzip 압축 전체 데이터 포함)은
  [data/README.md](data/README.md) 참고

## 실행 방법

```bash
pip install -r requirements.txt
jupyter notebook notebooks/
```

저장소에 gzip으로 압축된 전체 데이터(`data/incident_data.csv.gz`)가 포함되어 있어
클론만 하면 별도 다운로드 없이 바로 실행할 수 있다. `src/load_data.py`의 `load()`가
이 파일을 자동으로 읽는다.

## 분석 결과

### 01. 데이터 개요 (EDA)

623,188행, 15개 컬럼, 결측치·기간·기본 분포를 확인하는 단계로 별도의 차트는 생성하지
않는다.

- 돌발구분 대분류는 **기타돌발**(212,606건) → **공사**(201,333건) → **교통사고**
  (146,227건) → 기상(37,702건) → 기타(12,311건) → 재난(13,009건) 순이다.
- 데이터 기간은 2024-11-06 ~ 2025-10-31로 정확히 1년 치다.

### 06. 돌발상황 처리시간 분석

`돌발종료일시 - 돌발일시`로 처리시간(분)을 계산해 도로타입별 처리 속도를 비교한다
(진행중 건·데이터 오류 제외, 총 257,038건 분석).

![도로타입별 처리시간](outputs/figures/21_duration_by_road_type.png)

- 모든 도로타입에서 중앙값이 정확히 30분으로 나타난다. 처리 완료 건의 **59.3%가 정확히
  30분**으로 기록돼 있어, 이는 실측 처리시간이라기보다 **종료시각 미입력 시 시스템이
  채워 넣는 기본값일 가능성이 높다** — 상세 분석 목록 참고.

![처리시간 히스토그램](outputs/figures/22_duration_histogram_0_60min.png)

- 60분 이내에 종료 처리된 비율은 79.5%다. 30분 지점에 나타나는 뾰족한 스파이크가 위
  데이터 품질 이슈를 시각적으로도 보여준다.

### 04. 위험도 스코어링

각 돌발 레코드에 **위치(0~20) · 돌발유형(0~25) · 차로통제(0~40) · 시간대(0~15)** 4개
항목을 정규식/키워드 기반으로 채점해 0~100점의 `risk_score`를 산출한다.

![위험도 점수 분포](outputs/figures/11_risk_score_distribution.png)

- 전체 위험도 점수는 평균 약 35점, 중앙값 35점 수준에 분포한다.

![카테고리별 평균 위험도](outputs/figures/12_avg_risk_score_by_category.png)

- 사고가 평균 61.0점으로 가장 위험도가 높은 카테고리이고, 역주행(55.2점)·화재사고
  (50.7점)·작업(47.1점)·고장(45.2점)이 뒤를 잇는다.

![위험기여도 Top5](outputs/figures/13_risk_contribution_top5.png)

- 빈도 × 평균위험도로 계산한 위험기여도는 **작업(약 901만) > 사고(약 879만) > 고장
  (약 391만) > 차량증가/정체(약 251만) > 장애물(약 81만)** 순이다. 사고는 건당 위험도가
  가장 높지만, 건수가 압도적으로 많은 작업이 총 위험기여도로는 근소하게 앞선다.

## 종합 인사이트

- **작업과 사고가 가장 영향력이 큰 두 축이다.** 작업은 건수(191,487건)로, 사고는 건당
  위험도(평균 61.0점)로 각각 다른 방식의 "가장 중요한 카테고리"다. 실제 자원 배치
  우선순위는 위험기여도(빈도 × 영향도) 기준 작업 > 사고 순이다.
- **도로타입이 돌발 패턴을 가르는 가장 강한 설명 변수다.** 국가지원지방도(공사 62.3%),
  도시고속국도(교통사고 76.0%), 고속국도(기타돌발 43.4%)처럼 도로타입마다 지배적인
  돌발구분이 뚜렷이 다르고, 지역별 Top1 유형도 지역 고유의 특성보다는 그 지역에 어떤
  도로타입이 많이 지나는지에 좌우된다(예: 서울만 유일하게 교통사고 1위).
- **같은 도로타입 안에서도 편차가 크다.** 05번 딥다이브에서 확인했듯, 도시고속국도
  112번(공사 85.1%)이나 지방도 1020번(교통사고 73.3%)처럼 도로타입 평균과 크게 다른
  "예외 노선"들이 존재해, 전략을 짤 때는 도로타입 단위뿐 아니라 개별 노선 단위 점검이
  필요하다.
- **시간·요일·계절 모두 뚜렷한 리듬이 있다.** 평일 오전 9시(출근), 목~월요일(공사),
  여름철(사고 비율)처럼 돌발 유형별로 "언제 집중되는지"가 서로 다르므로, 동일한 대응
  체계보다는 유형별로 시점을 겨냥한 대응이 더 효율적일 것으로 보인다.
- **기록 데이터 자체의 한계도 발견했다.** 처리시간의 59.3%가 정확히 30분으로 찍혀 있는
  것은 실제 현장 대응 속도가 아니라 시스템 기본값일 가능성이 높아, 이 데이터만으로
  "실제 도로타입별 대응 속도"를 판단하기는 어렵다 — 아래 한계 참고.

## 알려진 한계

- **지역 분류**: `src/region_mapping.py`의 `지역` 컬럼은 원본 데이터에 없는 파생
  컬럼입니다. 위경도(X, Y) 좌표를 `geopandas`로 실제 시/도 행정경계(통계청 SGIS 기반,
  `data/boundaries/`)와 point-in-polygon 매칭해 분류하며, 행정경계 밖으로 판정되는
  좌표(해상/GPS 오차, 약 0.3%)는 최근접 시/도로 대체 배정합니다. 이전 버전(시/도 대표
  좌표와의 최근접 거리 근사)은 서울 인근 좌표가 실제로는 경기도인데도 서울로 오분류되어
  전체 1위가 서울로 나오는 문제가 있었는데, 실제 경계 기준으로 교체한 뒤에는 원본
  보고서와 동일하게 경기도가 1위로 나옵니다. 경계 데이터는 저장소 용량을 위해
  단순화(simplify tolerance 0.0005도)했으며, 이로 인해 전체 62.3만 건 중 172건(0.03%)만
  단순화 전과 다르게 분류됩니다.
- **위험도 스코어링의 텍스트 기반 판별**: `돌발내용` 컬럼이 자유 텍스트(반정형)라 정규식/
  키워드 매칭으로 위치·차로 정보를 추출합니다. 드물게 일부 표현(예: 지명에 숫자+교가
  없는 교량명)은 위치 점수에서 누락될 수 있습니다.
- **`도로번호`가 무의미한 도로타입이 있음**: `특별광역시도`와 `시군도`는 데이터상
  `도로번호`가 항상 0으로 기록돼 있어(다수의 일반 도로가 하나의 코드로 합쳐짐), 05번
  노트북에서는 이 두 도로타입만 `도로명` 기준으로 대체 분석했습니다.
- **처리시간 데이터의 시스템 기본값 의심 사례**: 06번 노트북에서 계산한 처리시간(분)은
  전체 처리 완료 건의 59.3%가 정확히 30분으로 기록돼 있어, 실측값이 아니라 종료시각
  미입력 시 시스템이 채워 넣는 기본값일 가능성이 있습니다. 또한 `공사` 카테고리는
  `돌발종료일시`가 실제 종료 시각이 아니라 수개월~수년 뒤의 **공사 예정 종료일**로
  기록된 경우가 있어(최대 약 2.7년), 평균값이 이 극단치에 크게 좌우됩니다 — 그래서
  도로타입별 비교는 평균이 아닌 중앙값·Q1·Q3를 기준으로 해석했습니다.
