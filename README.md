# 도로 돌발상황 분석

ITS 국가교통정보센터의 도로 돌발상황 데이터(62.3만 건, 2024-11 ~ 2025-10)를 분석해 돌발
유형·시간·도로별 발생 패턴을 찾고, 규칙 기반 스코어링으로 위험도를 정량화하는 프로젝트.

## 개요

국내 자동차 등록 대수는 2015년 약 2,099만 대에서 2024년 약 2,630만 대까지 매년 꾸준히
늘었다(국토교통부 시도별 자료 기준). 도로 위 교통량이 늘어난다는 것은 교통사고·공사·
차량고장 등 돌발상황이 발생할 여지도 함께 늘어난다는 뜻이고, 이는 곧 혼잡·지체·안전사고
위험 증가로 이어져 도로를 이용하는 사람들의 일상에 영향을 준다. 이 프로젝트는 돌발상황
데이터 자체를 뜯어봐서 (1) 발생 패턴을 찾고 (2) 어떤 상황이 실제로 더 위험한지 정량화하고
(3) 교통운영에 참고할 시사점을 도출하는 것을 목표로 한다.

| 핵심 결과 | 수치 |
|---|---|
| 데이터 규모 | 원본 API 수집 636,320건 → 전처리 후 623,188건 |
| 가장 많이 발생하는 유형 | 작업 191,487건 (30.7%) |
| 건당 위험도가 가장 높은 유형 | 사고 (평균 61.1점 / 100점) |
| 위험기여도(빈도×평균위험도) 1위 | 작업 (약 901.8만) — 근소하게 사고(약 880.9만)를 앞섬 |
| 돌발 1위 지역 | 경기도 163,402건 (26.2%) |
| 데이터 품질 이슈 발견 | 처리 완료 건의 59.3%가 정확히 30분으로 기록 — 시스템 기본값 의심 |

- 출처: [ITS 국가교통정보센터](https://www.its.go.kr) 오픈데이터 API (돌발정보)
- 수집기간: 2024-11-01 ~ 2025-10-31 (1년, API 수집 기준)

## 피처 엔지니어링

원본 CSV에는 없는 파생변수를 `src/load_data.py`, `src/region_mapping.py`에서 생성한다.
`요일`/`요일구분`은 원본 팀의 전처리 단계에서 이미 만들어져 raw CSV에 포함돼 있다.

| 변수명 | 생성 로직 | 목적/활용처 | 생성 위치 |
|---|---|---|---|
| `hour` | `돌발일시.dt.hour` | 시간대별 패턴(02, 04, 06번 노트북) | `load()` 호출 시점 |
| `month` | `돌발일시.dt.month` | 월별 트렌드(02번) | 〃 |
| `season` | `month` → 봄(3-5)/여름(6-8)/가을(9-11)/겨울(12-2) 매핑 | 계절별 분석(02번) | 〃 |
| `지역` | 위경도(X, Y) → `geopandas`로 17개 시/도 행정경계와 point-in-polygon 매칭, 실패 시(약 0.3%) 최근접 시/도로 대체 | 지역별 분석(03번) | `region_mapping.assign_region()` |
| `요일` | `돌발일시` 기준 영문 요일 | 요일별 패턴(02번) | 원본 전처리(raw CSV에 이미 포함) |
| `요일구분` | `요일` → 평일/주말/공휴일 분류 | 평일-주말 비교(02번) | 원본 전처리(raw CSV에 이미 포함) |

### 지역 매핑 방법론

`지역` 컬럼은 원본 데이터에 없어 위경도로부터 새로 만들어야 하는 파생 변수다. 두 가지
방식을 시도했다.

1. **(이전 버전) 최근접 중심점 근사**: 17개 시/도의 대표 좌표(위경도 1쌍)와의 유클리드
   거리만으로 가장 가까운 시/도를 배정. 구현이 간단하지만 서울처럼 면적이 작고 주변이
   경기도로 둘러싸인 지역은 실제로는 경기도 행정구역에 속한 좌표까지 서울로 잘못
   배정하는 문제가 있었다 — 이 방식으로는 전체 1위가 (원본 보고서와 다르게) 서울로
   나왔다.
2. **(현재 버전) geopandas point-in-polygon**: 통계청 SGIS 2018년 시/도 경계
   ([southkorea/southkorea-maps](https://github.com/southkorea/southkorea-maps) GeoJSON,
   `data/boundaries/`, 저장소 용량을 위해 simplify tolerance 0.0005도로 단순화)에 대해
   실제 폴리곤 포함 여부를 검사한다. 경계 밖으로 판정되는 좌표(해상/GPS 오차, 약 0.3%)는
   `sjoin_nearest`로 최근접 시/도에 배정한다.

방식을 바꾼 뒤 전체 1위가 원본 보고서와 동일하게 **경기도**로 나왔다(2위 이하는 다르며,
[원본 보고서와의 차이점](#원본-보고서와의-차이점) 참고).

## 종합 인사이트

원본 보고서 3장의 인사이트를 이번 코드 실행 결과 기준 수치로 재구성했다.

- **작업과 사고가 가장 영향력이 큰 두 축이다.** 작업은 건수(191,487건, 30.7%)로, 사고는
  건당 위험도(평균 61.1점)로 각각 다른 방식의 "가장 중요한 카테고리"다. 위험기여도(빈도
  × 영향도) 기준으로는 작업(약 901.8만) > 사고(약 880.9만) 순으로 근소하게 갈린다.
- **도로타입이 돌발 패턴을 가르는 가장 강한 설명 변수다.** 국가지원지방도(공사 62.3%),
  도시고속국도(교통사고 76.0%), 고속국도(기타돌발 43.4%)처럼 도로타입마다 지배적인
  돌발구분이 뚜렷이 다르고, 지역별 Top1 유형도 지역 고유의 특성보다는 그 지역에 어떤
  도로타입이 많이 지나는지에 좌우된다(서울만 유일하게 교통사고 1위).
- **같은 도로타입 안에서도 편차가 크다.** 도시고속국도 112번(공사 85.1%), 지방도 1020번
  (교통사고 73.3%)처럼 도로타입 평균과 크게 다른 예외 노선이 존재해, 전략을 짤 때는
  도로타입 단위뿐 아니라 개별 노선 단위 점검이 필요하다.
- **시간·요일·계절 모두 뚜렷한 리듬이 있다.** 평일 오전 9시(출근), 목~월요일(공사),
  여름철(사고 비율)처럼 돌발 유형별로 "언제 집중되는지"가 서로 다르므로, 유형별로 시점을
  겨냥한 대응이 더 효율적일 것으로 보인다.
- **기록 데이터 자체의 한계도 발견했다.** 처리시간의 59.3%가 정확히 30분으로 찍혀 있는
  것은 실제 현장 대응 속도가 아니라 시스템 기본값일 가능성이 높아, 이 데이터만으로 "실제
  도로타입별 대응 속도"를 판단하기는 어렵다.

## 알려진 한계

- **위험도 스코어링의 텍스트 기반 판별**: `돌발내용` 컬럼이 자유 텍스트(반정형)라 정규식/
  키워드 매칭으로 위치·차로 정보를 추출한다. 드물게 일부 표현(예: 지명에 숫자+교가 없는
  교량명)은 위치 점수에서 누락될 수 있다.
- **`도로번호`가 무의미한 도로타입이 있음**: `특별광역시도`와 `시군도`는 데이터상
  `도로번호`가 항상 0으로 기록돼 있어(다수의 일반 도로가 하나의 코드로 합쳐짐), 05번
  노트북에서는 이 두 도로타입만 `도로명` 기준으로 대체 분석했다.
- **처리시간 데이터의 시스템 기본값 의심 사례**: 06번 노트북 참고 — 처리 완료 건의
  59.3%가 정확히 30분으로 기록돼 실측값이 아닐 가능성이 높다.
- **원본 데이터 자체의 구조적 한계(원본 보고서에서도 지적됨)**: 이 프로젝트는 원본
  보고서와 동일한 ITS 원천 데이터를 쓰기 때문에 아래 한계도 그대로 물려받는다.
  - 실제 교통량(차량 통행량) 데이터가 없어, 돌발 건수만으로 원인을 추론하는 데 그친다.
  - 공사·기타돌발 유형은 실제보다 적게 기록되는 경향이 있고, 돌발이 사후 보고 형식으로
    입력되는 구조라 `돌발일시`가 실제 발생 시각보다 늦게 기록될 수 있다 — 06번 노트북에서
    발견한 "처리시간의 59.3%가 정확히 30분" 현상도 이런 보고 체계상의 특성과 무관하지
    않을 것으로 보인다.

## 실행 방법

```bash
pip install -r requirements.txt
jupyter notebook notebooks/
```

저장소에 gzip으로 압축된 전체 데이터(`data/incident_data.csv.gz`, 약 21.5MB)가 포함돼
있어 클론만 하면 별도 다운로드 없이 바로 실행할 수 있다. `src/load_data.py`의 `load()`가
이 파일을 자동으로 읽는다.

```
.
├── data/                          # 전체 데이터(gzip), 샘플, 스키마 안내, 행정경계
├── src/                           # load_data / region_mapping / plot_config
├── notebooks/                     # 01_eda ~ 06_accident_duration
├── outputs/figures/               # 각 노트북 실행 결과 PNG
└── requirements.txt
```
